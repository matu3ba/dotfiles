networkingMode
| networkingMode | Core Behavior                  | Primary Benefit                  | Biggest Drawback                   |
+----------------+--------------------------------+----------------------------------+------------------------------------+
| nat (Default)  | Hidden behind a virtual Windows| Strong network isolation; unique | Blocked by restrictive corporate   |
|                | switch layer (Hyper-V NAT).    | guest-only IP footprint.         | VPNs and endpoint security tools.  |
+----------------+--------------------------------+----------------------------------+------------------------------------+
| mirrored       | Shares/mirrors host network    | Native IPv6, Multicast support,  | Port collisions (cannot bind same  |
|                | adapters directly into Linux.  | and high corporate VPN/Proxy sync| port on host and WSL at once).     |
+----------------+--------------------------------+----------------------------------+------------------------------------+
| virtioproxy    | Paravirtualized proxy layer    | Bypasses strict endpoint agents  | High DNS lookup latency; restricted|
|                | acting as an outbound fallback.| to ensure basic outward internet.| inbound connections from host/LAN. |
+----------------+--------------------------------+----------------------------------+------------------------------------+
| bridged        | Attaches directly to physical  | WSL behaves like a separate bare-  | Deprecated; complex setup; fails |
|                | LAN via a dedicated vSwitch.   | metal machine on the local network.| entirely on Wi-Fi connections.   |
+----------------+--------------------------------+----------------------------------+------------------------------------+
| none           | Suppresses guest virtual NIC   | Complete local sandbox isolation | Zero communication network paths;  |
|                | generation entirely.           | for secure offline execution.    | breaks host-to-guest localhost.    |
+------------------+------------------------------+----------------------------------+------------------------------------+

hyper-v
* nat: itnernal switch (visible to host/VM but not LAN) with windows handling internet connection sharing on top of it.
* bridged: bind to physical network adapter (Ethernet/wifi) with VM getting own IP from home/office router.
* none: private switch/disconnected: isolated VM entirely, connection only between VMs on same switch, neither Windows host nor internet can reach it
* mirrored: does not exist
* mirrored: no lightweight fallback proxy layer, network simply disconnects

==design
* Based on single hyper-v based VM
* No good isolation across WSL instances
* very buggy due to various trade-offs on compatibility
  - systemd based applications have horrible behavior, best to eliminate systemd
* lots of race conditions
* uses variant of linux kernel on "utility VM"
  - systemd, dbus, session management adjusted by nested namespaces on windows host os
  - filesystems /mnt/c are connected via unreliable 9P protocol
* why 9p?
  - instead of SMB/CIFS/NFS direct communication over virtual bus channels/vsockets of vSOckets without TCP/IP network overhead
  - why still bad
    * implementation bugs, file locking (NTFS with mandatory locking vs Linux advisory locking)
    * NTFS kernel lcoks would have need write locks on every linux write access, which
      would have frozen io performance
      - this breaks rootless podman on id/permissions
* dynamic memory
  - linux cache problem
    * linux kernel uses unused RAM as page cache to improve perf
    * cgroup feature into subssytem (autoMemoryReclaim=gradual) to force linux kernel to drop
      page cache cyclically
      - this can create instabilities in container engines
=> unrecommended for
  - security of file permissions
  - stable sockets
  - stable script automation
* no inversion of control attempt whatsoever, only adding more features to the 2 million LOC systemd monolith
  - Poettering added support for Trusted Graphical Sessions
  - enables Deterministic Boot-Fuzzing
  - enables Hypervisor-enclaves & "Zero-Trust" Embedded Architecture
    (process isolation and permission control based on type 1 hypervisor)
  - enables boot sequence as pure, stateless fn (from the kernel perspective)
    * snapshotting, rollback etc possible
