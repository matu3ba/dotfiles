==design
* no overview on clocks, sync, scheduling and hardware emulation in context
of userspace, systemspace and accelerated simulation (kvm)
* QEMU_CLOCK_VIRTUAL for guest events
====storage_model
* MemoryRegion
  - containers for grouping (potentially overlapping) subregions
  - RAM regions for direct in host storage allocated byte arrays to be directly used by guest
  - MMIO regions accessing logic areas. read and write access creates callback in host to simulate periphery
  - aliases for mirroring existing region into other space in address space
* AddressSpace as "viewpoint" of hw component with memory region as root
  - example: viewpoint of CPU or DMA controller on storage
* FlatView as on-demand compiled flat, non-overlapping view of memory regions
* RAMBlock to manage allocations in host memory (ie view mmap), which MemoryRegion points to
====MTTCG_consistency_model
* each virtual CPU (vCPU) runs on default on own host thread
* Big Qemu Lock (BQL) aka IO thread mutex for access on emulated hw devices (MMIO)
  or interrupt changes to prevent race conditions
  - in contrast to parallel execution by vCPUs in RAM
* C11 memory model with translation of atomics in host barriers
