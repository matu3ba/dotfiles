====composability
Have to use dedicated checks in Containerfile or get silent broken errors,
because there is on semantic convention on default user:
FROM docker.io/library/node:26-alpine
ARG UID
ARG GID
# 1 /etc/passwd must contain
# root:x:0:0:root:/root:/bin/sh
# $USER:x:UID:GID::/home/$USER:/bin/sh
# 2 /home/$USER must be empty
# 3 UID and GID in container must match
RUN set -e; \
    echo "=== Validating /etc/passwd ===" && \
    PASSWD_LINES=$(grep '/bin/sh$' /etc/passwd) && \
    COUNT=$(echo "$PASSWD_LINES" | wc -l) && \
    if [ "$COUNT" -eq 2 ]; then echo "[OK] Found exactly 2 entries with /bin/sh"; else echo "[FAIL] Expected 2 entries with /bin/sh, found $COUNT"; exit 1; fi && \
    if echo "$PASSWD_LINES" | grep -q '^root:x:0:0:root:/root:/bin/sh$'; then echo "[OK] root entry valid"; else echo "[FAIL] root entry malformed"; exit 1; fi && \
    if echo "$PASSWD_LINES" | grep -q "^[^:]*:x:${UID}:${GID}::/home/[^:]*:/bin/sh$"; then echo "[OK] Non-root entry valid (UID=${UID}, GID=${GID})"; else echo "[FAIL] Non-root entry with UID=${UID} GID=${GID} not found"; exit 1; fi && \
    NON_ROOT_USER=$(echo "$PASSWD_LINES" | grep -v '^root:' | cut -d: -f1) && \
    echo "[OK] Extracted user: $NON_ROOT_USER" && \
    echo "" && \
    echo "=== Validating /home ===" && \
    UNEXPECTED=$(find /home -mindepth 1 -maxdepth 1 ! -name "$NON_ROOT_USER" 2>/dev/null || true) && \
    if [ -z "$UNEXPECTED" ]; then echo "[OK] /home clean"; else echo "[FAIL] Unexpected entries in /home"; exit 1; fi && \
    if [ ! -d "/home/$NON_ROOT_USER" ] || [ -z "$(find "/home/$NON_ROOT_USER" -type f 2>/dev/null)" ]; then echo "[OK] /home/$NON_ROOT_USER empty"; else echo "[FAIL] /home/$NON_ROOT_USER is not empty"; exit 1; fi && \
    echo "=== Validating UID + GID match ===" && \
    USER_ID=$(id -u "$NON_ROOT_USER") && \
    USER_GID=$(id -g "$NON_ROOT_USER") && \
    if [ "$USER_ID" = "$UID" -a "$USER_GID" = "$GID" ]; then echo "[OK] User UID, GID matches"; else echo "[FAIL] UID, GID mismatch: expected $UID/$GID, got $USER_ID/$USER_GID"; exit 1; fi && \
    echo "[OK] All validations passed"

WORKDIR /app
RUN chown ${UID}:${GID} /app
USER ${UID}:${GID}

What OCI Left Unsolved
* No signature enforcement — OCI spec defines where to store attestations, not
  how to validate them.
* No semantic standard for security metadata — No way to declare UID/GID,
  capabilities, user assumptions in OCI spec.
* No vulnerability lifecycle management — OCI has no concept of "stale SBOM" or
  continuous re-scanning.
* No base image security — No way to recursively verify that dependencies (base
  images) are themselves secure.

======docker_security_bad
Docker does not support uid= or gid= mount options like some other tools do.
The mount preserves the host's original UID/GID ownership.
Docker only applies USER ownership to mounts that don't exist on the host. For
existing host directories, it preserves their original ownership.
Use --mount instead of -v for explicitness.
https://github.com/opencontainers/runtime-spec/blob/main/config.md

docker has no flag '--userns keep-id', so security is very inconvenient.
relabeling neither helps:
>cat /etc/docker/daemon.json
{
  "userns-remap": "user:user"
}
>sudo systemctl restart docker
>cat Containerfile.npm
FROM docker.io/library/node:26-alpine
WORKDIR /app
RUN addgroup -g 1001 -S nodejsuser && adduser -S nodejsuser -u 1001
COPY --chown=nodejsuser:nodejsuser . .
RUN mkdir -p /app/node_modules && chown -R nodejsuser:nodejsuser /app/
USER nodejsuser
>docker build -t alpine-npm:26 -f Containerfile.npm .
>docker run --rm -v ./client:/app -v /app/node_modules alpine-npm:26 ls -ld /app
>docker run --rm -v ./client:/app -v /app/node_modules alpine-npm:26 sh -c "npm install --verbose && rm -rf node_modules"
vs podman:
>podman run --rm --userns=keep-id -v ./client:/app:z -v /app/node_modules alpine-npm:26 sh -c "npm install --verbose && rm -rf node_modules"

https://docs.podman.io/en/latest/markdown/podman-run.1.html
- uidmap, gidmap

* uidMappings / gidMappings on mounts (optional)
* Uses mount_setattr(MOUNT_ATTR_IDMAP) (Linux 5.12+)
* Options: idmap or ridmap flag
Rootless mode and userns-remap mode map container UIDs and GIDs to the host differently.
    In userns-remap mode, container UID 0 is mapped to the first subordinate UID listed in
    /etc/subuid for the remap user, and container UID n is mapped to subuid + n.
    In rootless mode, container UID 0 is mapped to the host UID of the user running rootless
    Docker (the result of id -u); container UID n (for n >= 1) is mapped to subuid + (n - 1).
GIDs follow the same rules using /etc/subgid.
docker: This difference matters when setting file permissions on bind-mounted directories: in
rootless mode, files owned by your host user appear as owned by root inside the container.

====permission_problems
1 Permissions Denied (host root files)     | rm -fr obj/ bin/
2 Rootless volume fail (nobody masking)    | Use --userns=keep-id (container id=host id except for root)
                                             xor --userns=nomap (container root=host root)
                                             xor --userns=auto (max isolation)
                                             xor --userns=keep-id:uid=UID,gid=GID (--uidmap/--gidmap replacement)
3 Cross-container label conflicts by ':z'  | :Z (private, non-shared) xor :z (relabel according to /etc/subuid)
4 Unwanted SELinux UID interaction         | :Z + chcon (adjust private files, if needed) xor named volumes
5 Unmapped namespace problems              | podman unshare chown xor --userns=keep-id
6 apparmor problems                        | cat /sys/module/apparmor/parameters/enabled

OCI runtime (runc/crun) should never map host root (uid=0) to container uid 0
in rootless mode. The spec defines UID maps that preserve isolation
* Container UID 0 → host UID (your user's UID, e.g. 1000)
* Container UID 1+ → host UID range from /etc/subuid (e.g. 100000–165535)

making user workflows horrible.
without overlay-fs explicitly configured
$ podman run --rm --userns=keep-id alpine:latest ls /

Permission denied: OCI permission denied
and with overlay-fs:
$ podman run --rm --userns=keep-id alpine:latest ls /
Error: runc: runc create failed: unable to start container process: error during container init: error preparing rootfs: remount-private

====mount_order
  ref https://blog.quarkslab.com/digging-into-the-oci-image-specification.html
  ref https://oneuptime.com/blog/post/2026-03-17-mount-flag-vs-volume-flag-podman/view
  >podman run --rm -v ./client:/app:z -v /app/node_modules alpine-npm:26 sh -c "npm ci --verbose && npm update --verbose"
  Explanation
  >docker build -t image dockerfile
  does build based on package-lock.json /app/node_modules
  and then we chmod -R 555 node_modules and the whole things is stored
  in the private image layer with owner USER root.
  >podman run -v ./client/:/app:z -v /app/node_modules image
  Then first ./client binds to /app and overwrites everything
  with the use permissions of the current USER user.
  Thereafter the private volume /app/node_modules of the image
  mounts into /app/node_modules keeping the permissions.

  Hence /app/node_modules has owner USER user
  and /app/node_modules/* has owner USER root.
