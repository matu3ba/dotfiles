==podman_desktop
1 use installer and follow menus
2 do not allow network access
3 Podman Setup: recreate default machine to fix
  >podman ps
  "Error: unable to connect to Podman socket"
via
  podman machine list
  podman machine stop
  podman machine rm podman-machine-default
  podman machine init
  podman machine start
and check podman socket connectivity
  podman info
4 kubectl Setup: use correct config or create kind cluster to fix
  >kubectl get pods
  "E0709 .. "Unhandled Error" err="couldn't get current server API group list:
  Get .. et \"http://localhost:8080/api?timeout=32s\": dial tcp 127.0.0.1:8080:
  connectex: Could not establish connection, because target computer refused
  connection."
via
  kubectl config current-context
  kubectl config current-context
  kubectl config use-context docker-desktop
or
  Podman Desktop > Settings > Kubernetes > Goto Resources > Kind > Create new Kind cluster or
  Settings > Resources > Kind > Create new Kind cluster
5 Additional cluster checks
  kubectl cluster-info
  kubectl get nodes
  kubectl get all -A

alternatively install manually from wsl https://community.veeam.com/kubernetes-korner-90/be-kind-with-podman-and-cloud-provider-kind-9842
kind create cluster
kind get cluster
kubectl get nodes
go install sigs.k8s.io/cloud-provider-kind@latest
sudo install ~/go/bin/cloud-provider-kind /usr/local/bin
kubectl label node kind-control-plane node.kubernetes.io/exclude-from-external-load-balancers-
cloud-provider-kind -enable-lb-port-mapping

==debug

  podman ps -a --format "{{.Names}}\t{{.Image}}"

==autostart
https://linuxhandbook.com/courses/podman/autostart-podman-containers/
* daemonless means that we need help from pid 1 to restart the services
>podman generate systemd --new --name CONTAINER_NAME
>podman generate systemd --new --name CONTAINER_NAME -f
>mv -v CONTAINER_NAME.service ~/.config/systemd/user/
root>sudo systemctl daemon-reload
root>sudo systemctl enable SERVICE_NAME.service
>systemctl --user daemon-reload
>systemctl --user enable SERVICE_NAME.service

maybe necessary depending on OS
>systemctl --user enable podman-restart.service

user session for user spawned at boot and kept around after logouts from GUI etc
>sudo loginctl enable-linger
